# SpecProof

> **Turn document-only API specs into verified, cited contracts — and prove whether your code keeps them.**

Built for the IBM Bob 2.0 Hackathon (lablab.ai, Sep 25–27, 2026) · MIT License

---

## The problem

Many integrations are governed by specifications that exist **only as documents** — PDF, Word, Excel. Vendors, payment networks and tax authorities publish them; developers read hundreds of pages by hand, transcribe them into code, and miss it when the document is wrong or changes.

Machine-readable tooling (OpenAPI diffing, contract testing) can't help, because there is no machine-readable spec. So teams hand-convert — and hand conversions carry disclaimers like *"may contain omissions or errors."*

## What SpecProof does

1. **Reads the spec document** with IBM Bob 2.0 document understanding. Subagents extract one chapter each, in parallel.
2. **Produces a structured contract where every field carries a citation** — page number plus a verbatim quote.
3. **Verifies every claim deterministically.** No model is ever allowed to mark its own work correct:
   - citation quotes must actually exist on the cited page;
   - table rows must match the claimed required-flag and type;
   - the document's own request and response samples must validate against the extracted contract.
4. **Loops:** failed items get precise feedback and are re-extracted (at most 2 retries). What still fails is either quarantined (extraction untrusted) or, when both sides are grounded in the document, **reported as a defect in the spec itself**.
5. **Checks real code against the contract:**
   - the endpoints it calls;
   - its data models;
   - whether its models can parse the document's own response samples.
6. **Reports everything** as a self-contained HTML evidence pack, plus SARIF and JSON.

## Demo target (verified before kickoff — see `docs/VERIFIED_FACTS.md`)

| Input | Details |
|---|---|
| Spec | Ubiquiti **UniFi Access API** official PDF: 194 pages, ~107 endpoints, 106 request samples, 99 response samples |
| Reference | Community OpenAPI conversion (MinerU + Claude), MIT |
| Code under test | `py-unifi-access`: async Python client with Pydantic v2 models, MIT |

**Example of a real finding class:** the PDF defines `visit_reason` as the enum `{Interview, Business, Cooperation, Others}`, yet two of its own request samples send `"Interviemw"`. That is a spec self-inconsistency SpecProof is designed to surface — with page citations for both sides.

## Quickstart

```bash
git clone <this repo> && cd specproof
make setup                 # venv + deps + pre-commit
make fetch                 # downloads pinned sources, verifies SHA-256
make pipeline              # deterministic stages on committed contracts
open artifacts/report/index.html
```

Extraction itself runs inside IBM Bob 2.0. Use the `spec-auditor` mode with the `/sp-extract` command; see `START_HERE.md`.

## Prior art and our delta

LLM spec extraction and spec-to-code checking already exist; see [`docs/PRIOR_ART.md`](docs/PRIOR_ART.md). Their shared weakness is **unverified output**. SpecProof adds three things:
- deterministic verification of every extracted claim against the document's own text and samples;
- a bounded self-correction loop that separates extraction errors from genuine defects in the spec;
- native IBM Bob 2.0 packaging.
