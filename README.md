## The problem

Many integrations are governed by specifications that exist **only as documents** — PDF, Word, Excel. Vendors, payment networks and tax authorities publish them; developers read hundreds of pages by hand, transcribe them into code, and miss it when the document is wrong or changes.

Machine-readable tooling (OpenAPI diffing, contract testing) can't help, because there is no machine-readable spec. So teams hand-convert — and hand conversions carry disclaimers like *"may contain omissions or errors."*

## What SpecProof does

1. **An AI extractor reads the spec document** section by section and writes a structured contract where **every field carries a citation**: a page number plus a verbatim quote.
2. **Deterministic code verifies every claim.** No model is ever allowed to mark its own work correct:
   - citation quotes must actually exist on the cited page;
   - table rows must match the claimed required-flag and type, and every detected row must be in the contract;
   - the document's own request and response samples must be copied verbatim and completely, and must validate against the extracted contract.
3. **Loops:** failed items get precise, machine-generated feedback and are re-extracted (at most 3 attempts). What still fails is quarantined. When both sides of a conflict are grounded in the document, it is **reported as a defect in the spec itself**.
4. **Compares** the verified contract with a community OpenAPI conversion of the same PDF, citing the PDF for every difference.
5. **Checks real code against the contract:** the endpoints a client calls, its data models, and whether its models accept the document's own response samples.
6. **Reports everything** as a self-contained HTML evidence pack, plus SARIF and JSON. Every finding stays a *candidate* until a human confirms it.

## Quickstart

```bash
git clone <this repo> && cd specproof
make setup                 # venv + deps + pre-commit
make fetch                 # downloads pinned sources, verifies SHA-256
make pipeline              # deterministic stages on the committed contracts
open artifacts/report/index.html
```

## Reproduce

```bash
make setup && make fetch   # ~1 min: Python 3.11+, sources pinned by SHA-256
make pipeline              # ingest is the slow step (1-2 min on first run, cached after)
make eval                  # gates metrics against eval/thresholds.yaml
make test-e2e              # end-to-end and real-source tests
```

The client replay (conformance step C3) needs an interpreter that satisfies the client's own requirement (`py-unifi-access` needs Python >= 3.12). Create a venv with it, install the client, and run `make pipeline REPLAY_PYTHON=<path to that python>`.

Real-document runs exposed a series of verifier gaps (for example, curl requests without bodies, samples with several examples, layout-wrapped strings); each fix is a separate `fix:` commit with a regression test.

## Prior art and our delta

LLM spec extraction and spec-to-code checking already exist; see [`docs/PRIOR_ART.md`](docs/PRIOR_ART.md). Their shared weakness is **unverified output**. SpecProof adds:
- deterministic verification of every extracted claim against the document's own text and samples;
- a bounded self-correction loop that separates extraction errors from genuine defects in the spec;
- conformance checks that replay the document's samples through real client models.
